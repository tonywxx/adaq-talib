# ADR 0001: API 保真度模型采用惯用 Rust 封装（模型 B）

- 状态：已采纳（2026-08-09）
- 决策人：用户 + WorkBuddy（grilling 会话）

## 背景

需求同时要求：
1. "零偏差复刻 TA-Lib 0.7.1 全部 API、算法逻辑、入参出参规则"；
2. "整体工程结构、命名规范、依赖配置、文档、导出接口严格遵守 crates.io 全部上架规则与 Rust 官方库开发规约"。

TA-Lib 0.7.1 原版是扁平 C 风格 API（`TA_SMA` 等函数、指针入参、`outBegIdx`/`outNbElement`、返回 `TA_RetCode`），与 Rust 规约要求的惯用、安全、文档完备 API 直接冲突。

## 决策

公共 API 采用惯用 Rust 形态：
- 入参为切片（`&[f64]` 等）；
- 出参为 `Result<Output, Error>`；
- 多输出指标（如 BBANDS 返回上轨/中轨/下轨）以结构体或元组返回；
- 内部算法逻辑与数值与原版逐项 1:1 一致。

不为每个 C 函数做字面 1:1 镜像（即不采用模型 A）。是否额外提供底层 `sys` 镜像层（模型 C）为未决项，待后续评估。

## 权衡

- 优点：满足 crates.io 最佳实践、内存安全、ergonomics 好、doc-comment 友好；数值层面仍零偏差。
- 缺点：期望 C 调用约定的外部代码无法逐函数直接对照（可由独立 `sys` 层补足）。
- 难以回退：发布后改变公共 API 形态会破坏 SemVer 兼容性。

## 影响

- 源码按指标类别划分模块（重叠研究 / 动量 / 成交量 / 波动率 / …）。
- 错误模型采用 `Result` + 错误枚举（语义映射 `TA_RetCode`），而非返回裸 `RetCode`。
- 多输出指标需设计返回值结构体。
