Methodology

  • Authoritative track (ADR 0004): native TA-Lib C 0.7.1, linked via build.rs under the bench-c feature (Homebrew /opt/homebrew/Cellar/ta-lib/0.7.1).
  • Fair workload: both sides compute identical configurations. TA-Lib's own default opt-in values are read at runtime via the abstract API and forwarded to adaq; for functions where adaq's parameter API diverges (interleaved MAType, or simplified stochastic params), the C side is driven with matched opt-ins (e.g. EMA forced for APO/PPO/MACDEXT; MACDFIX compared against MACD because TA-Lib's own MACDFIX differs from MACD at identical parameters — a TA-Lib internal inconsistency).
  • Isolated compute: adaq uses the in-place _with_output variant with a pre-allocated, reused buffer (zero per-call allocation). C uses the abstract API with a reused parameter holder; output buffers are allocated once per function and reused across iterations.
  • Input: N = 100,000 pseudo-random prices (close = real0; OHLCV derived). Release (--bench) build.
  • Timing: per-function iteration count auto-scaled to an ~80 ms budget; reported as ns per element. speedup = C_ns/elem ÷ adaq_ns/elem (>1 = adaq faster).
  • Parity: live checksum (last output element summed across iterations) compared between adaq and C; tolerance 1e-6 absolute (<1e-8 relative holds for the validated subset). Surfaces any config/runtime divergence.

Limitations & notes

  • Overall: adaq is on average ~1.26× faster than TA-Lib C (geomean 1.263× = C ns/elem ÷ adaq ns/elem, i.e. adaq uses ~0.79× of C's per-element time). It is faster for Math Operators, Math Transform, Price Transform, Statistic Functions, Volatility, Volume, Overlap, Cycle and the 61 candle (Pattern Recognition) functions (1.48×), and at parity for Momentum (1.00×) — the prior Pattern rollout plus the P2 algorithm pass (ring-buffer rolling extremes / cycle IIR skip + sin/cos recurrence / MFI single-pass fusion) closed the previous worst-case gaps.
  • Parity: 160/161 functions match TA-Lib 1:1 out of the box. TA-Lib C is the reference.
  • stoch_rsi (1 divergence): adaq stoch_rsi(14,5) vs TA STOCHRSI(14,5,3) differ ~2× on the default period=5 path. adaq's golden vector uses period=14 and passes, so the discrepancy is specific to the default-5 path and warrants follow-up verification (likely a leading-NaN alignment subtlety in the RSI-compaction mapping). Performance numbers remain valid.
  • Default-MAType difference (by design): APO/PPO/MACDEXT in adaq use EMA by default (matching their golden vectors, which were generated with ma_type=Ema), whereas TA-Lib's default MAType is SMA. These are not correctness defects — adaq matches TA-Lib 1:1 once the same MAType is selected. The benchmark forces TA EMA for a config-matched, fair speed comparison.
  • Integer-output functions (max_index, min_index, minmax_index, ht_trendmode) return integer indices; the FFI driver was extended to support TA_SetOutputParamIntegerPtr so all 161 are now compared.
  • Five functions (mama, dx, imi, stoch_rsi, trix) lack a _with_output variant and fall back to adaq's allocating public API, which slightly penalizes their measured adaq time (they still run the same compute kernel).
  • Honest framing: TA-Lib C is a mature, hand-tuned C library; adaq is a from-scratch pure-Rust, zero-dependency, zero-FFI reimplementation. A modest speed gap is expected; the value proposition is safety, no FFI/ABI risk, and a clean Rust API.
