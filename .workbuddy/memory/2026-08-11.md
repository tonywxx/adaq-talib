## 2026-08-11 (later) — P3-6 FMA-contraction pass SUPERSEDES the above P2/README numbers
- **Root cause of the EMA-family ~1.4× gap found:** GCC compiles TA-Lib C at `-O2` with
  `-ffp-contract=fast`, contracting `out = in*K + out*(1-K)` into ONE hardware FMA. `rustc` does NOT
  contract by default (no `-ffast-math`), so our 2-op `prev = (v[i]-prev)*k + prev` emits mul+add (2
  ops, different rounding). Fix: explicit `.mul_add()` at every recurrence site → single FMA, same
  rounding sequence as C, and faster. Applied in `src/core/mod.rs` (`ema_with_output` + nested EMA
  levels 1..=L), `src/overlap.rs` (`kama_with_output` ×2), `src/volume.rs` (`adosc_with_output` fast/
  slow EMA). 1:1 with prior Rust + with C; `cargo test` still **326/0**.
- **Effect:** `ema` 1.488→0.977, `kama` 1.484→1.069, `apo` 1.529→1.085, `ppo` 1.425→1.077,
  `t3` 1.325→0.999 (all → At parity); transitive `trix` 0.570→0.455, `ultosc` 0.871→0.786 (Faster).
- **FINAL (5-run median, rounds 14–18, post-FMA): 85 faster / 60 parity / 16 slower; geomean
  Rust/C = 0.786× (~1.27× faster than C).** The "82/54/25, 0.792×, median-of-3" figures in the P2
  note above are now OBSOLETE — superseded by this pass. Report §3.3 + both READMEs updated to
  median-of-5 and 85/60/16.
- **16 residual slower = genuine single-thread floors** (can't vectorize across time): dual-deque
  `minmax`/`minmax_index` + `midpoint` (~1.5–1.6×); sliding-window `mfi`/`willr`/`stoch_f`/`adosc`/
  `correl`; strict-recurrence `ht_phasor`/`ht_trendline`; `trange`; Pattern candle branches
  `cdl_engulfing`/`cdl_separatinglines`/`cdl_harami`/`cdl_longline`/`cdl_shortline`. The >2× path is
  parallelization/SIMD (gated per `NEXT-ACTIONS-perf.md` P3) — NOT single-thread micro-opt.

## 2026-08-11 (final) — P3-2 `midpoint` parallel PoC IMPLEMENTED & VERIFIED (user approved "ok")
- **Approach that WORKS (A 类双队列):** overlap-seed parallel chunking. New `src/parallel.rs`
  (`parallel_index_map`, `std::thread::scope` + `available_parallelism`, pure std → No-Deps-safe;
  default-off `parallel` feature). Each chunk overlaps the previous by `period-1` leading elements to
  seed the monotonic deque; the per-chunk `worker` REUSES the exact serial kernel, so output is 1:1
  by construction. `src/overlap.rs` splits `midpoint_serial_with_output` (kernel) /
  `midpoint_parallel_with_output` (chunk scheduler); `midpoint_with_output` auto-dispatches to
  parallel when `parallel` feature + `N≥8192`; added `midpoint_serial` / `midpoint_parallel` entries.
- **A/B (N=200_000, period=5, median-of-5, LCG):** serial ref ≈13.36 ns/elem → explicit parallel
  ≈6.43 ns/elem = **2.08× faster** than serial single-thread (feature-dispatch ≈8.06 ns/elem = 1.66×).
- **1:1 gate:** `tests/parallel_equality.rs` (feature-gated) passes for period ∈{1,2,3,5,10,14,30,64}
  + `N<8192` fallback; parallel == serial bit-for-bit (with NaN handling). Default `cargo test` still
  **326/0** (feature off → zero behavior change).
- **adosc (B 类严格 IIR): CANNOT use overlap-seed** — EMA is infinite-memory; carry-in needs the
  previous chunk's final EMA value (sequential dependency) → no parallel speedup. Only linear-recurrence
  parallel-scan could help, but that's future work needing 1:1 re-validation. So `adosc` stays a
  single-thread floor under this framework; documented the correction in NEXT-ACTIONS-perf.md P3-2.
- `minmax`/`minmax_index`/`willr`/`stoch_f` can reuse the SAME `parallel_index_map` (overlap `period-1`,
  kernel unchanged) — next steps if user wants to push more A-class floors below C.
