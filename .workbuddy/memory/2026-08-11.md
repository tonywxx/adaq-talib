## 2026-08-11 (later) — P3-6 FMA-contraction pass SUPERSEDES the above P2/README numbers
- **Root cause of the EMA-family ~1.4× gap found:** GCC compiles TA-Lib C at `-O2` with
  `-ffp-contract=fast`, contracting `out = in*K + out*(1-K)` into ONE hardware FMA. `rustc` does NOT
  contract by default (no `-ffast-math`), so our 2-op `prev = (v[i]-prev)*k + prev` emits mul+add (2
  ops, different rounding). Fix: explicit `.mul_add()` at every recurrence site → single FMA, same
  rounding sequence as C, and faster. Applied in `src/core/mod.rs` (`ema_with_output` + nested EMA
  levels 1..=L), `src/overlap.rs` (`kama_with_output` ×2), `src/volume.rs` (`adosc_with_output` fast/
  slow EMA). 1:1 with prior Rust + with C; `cargo test` still **326/0**.
- **Effect:** `ema` 1.488→0.977, `kama` 1.484→1.069, `apo` 1.529→1.085, `ppo` 1.425→1.077,
  `t3` 1.325→0.999 (all → At parity); transitive `trix` 0.570→0.455, `ultosc` 0.871→0.786 (Faster).
- **FINAL (5-run median, rounds 14–18, post-FMA): 85 faster / 60 parity / 16 slower; geomean
  Rust/C = 0.786× (~1.27× faster than C).** The "82/54/25, 0.792×, median-of-3" figures in the P2
  note above are now OBSOLETE — superseded by this pass. Report §3.3 + both READMEs updated to
  median-of-5 and 85/60/16.
- **16 residual slower = genuine single-thread floors** (can't vectorize across time): dual-deque
  `minmax`/`minmax_index` + `midpoint` (~1.5–1.6×); sliding-window `mfi`/`willr`/`stoch_f`/`adosc`/
  `correl`; strict-recurrence `ht_phasor`/`ht_trendline`; `trange`; Pattern candle branches
  `cdl_engulfing`/`cdl_separatinglines`/`cdl_harami`/`cdl_longline`/`cdl_shortline`. The >2× path is
  parallelization/SIMD (gated per `NEXT-ACTIONS-perf.md` P3) — NOT single-thread micro-opt.
